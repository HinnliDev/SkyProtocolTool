# Руководство Flows

[![English](https://img.shields.io/badge/lang-Русский-blue)](./flows.md)

Flows — сценарии из связанных нод. Сохранённый JSON может содержать URL,
тело и пользовательские заголовки. Не включайте в сценарий секретные значения,
если планируете поделиться им; используйте отдельные именованные секреты.

</div>

---

## Быстрый старт

1. Откройте Flows. Без выбранной карточки доступен пустой черновик.
2. Нажмите на свободное место canvas и выберите тип в Add node.
3. Выберите ноду и заполните нижние Node settings. Если панель скрыта,
   откройте её кнопкой нижней панели.
4. Добавьте Notification. Протяните выход Flow у заголовка первой ноды
   к входу у заголовка Notification.
5. В Notification text впишите, например, `Статус: {{status}} | {{response.msg}}`.
6. Нажмите Run, чтобы запустить сценарий.
7. Save создаёт карточку в Saved flows; последующие сохранения обновляют файл.

В пустом черновике Save, Run и Repeat недоступны. Для первого сохранения
достаточно одной ноды. Сохранение само по себе не запускает сценарий.

Готовые сценарии доступны в разделе [Примеры сценариев](#примеры-сценариев).

## Canvas и управление

- Перетаскивание свободного места перемещает камеру. Долгое нажатие и движение
  создают красную рамку выделения. Новая рамка добавляет ноды к уже выбранным.
- Одна выбранная нода доступна в Node settings; при нескольких панель неактивна.
  Перетаскивание выбранной ноды перемещает выделенную группу.
- Тап по свободному месту сначала снимает выделение; следующий открывает Add node.
- `+`, `−` и центр управляют масштабом. Процент показывает положение между
  минимальным и максимальным масштабом. При 25% и ниже тексты и иконки скрыты.
- Миникарта показывает граф и область просмотра. У края canvas камера движется
  автоматически при переносе нод, рамки выделения или соединения.
- Delete удаляет выбранные ноды. При переносе ноды можно отпустить её на Delete.
  Clear сразу очищает canvas; Undo может отменить очистку.
- Copy копирует выделение и связи внутри него. Paste сохраняет относительное расположение,
  назначает новые ID и обновляет ссылки на скопированные источники. Для группы иконка вставки
  белая, для одной ноды — её цвета. Внешние связи не копируются.
  Вставка размещает копию по центру текущего вида, наложение разрешено. Удержание Paste очищает буфер.
- Добавление новой ноды находит свободное место. Вместимость рассчитана по всему полю и самой
  крупной карточке с учётом масштаба шрифта (до 4464 нод стандартного размера).
  При достижении вместимости или нехватке места добавление недоступно;
  группа вставляется целиком, без частичной вставки.
- Undo/Redo восстанавливают настройки, расположение, ноды и соединения.
  Reset у верхних кнопок возвращает последнее сохранённое состояние.

При переключении или снятии выбора карточки несохранённые правки выбранного
сценария отбрасываются вместе с его Undo/Redo. Файл не изменяется, пока не нажато Save.
Карточки можно переименовать, добавить в избранное, переставить и удалить.
Обновление перечитывает папку; Import flow добавляет JSON.

## Соединения

Выход справа можно подключить к нескольким входам. Кружки подходящих входов
заполняются только во время переноса соединения.
При отпускании на пустом месте Add node создаёт сразу подключённую ноду.

Кружки у заголовка — порядок выполнения (Flow).
Остальные порты передают Method, URL/Endpoint, Headers, Body, Response и Status.
Любая связь задаёт зависимость: нода ждёт завершения **всех** входящих источников.
Condition пропускает неактивную ветку. Collect принимает и пропущенные ветки,
собирая только активные; остальным нодам нужны все активные входы.
Ноды без входов запускаются независимо. Циклы запрещены; Repeat повторяет весь граф.

Method, URL/Endpoint и Headers, связанные напрямую, берутся из источника;
их ручные настройки блокируются. Body, Notification text, Request contains
и Response contains остаются редактируемыми: подключение добавляет `{{переменную}}`,
а вы можете дописать свой текст. К одному такому полю можно подключить несколько портов.
Значения Condition и имена файлов Save/Read тоже поддерживают редактируемые шаблоны.
Вход Data у Collect собирает подключённые значения напрямую, без текстового поля.

Чтобы перенести существующую связь, возьмите её за входной кружок. Если связей
несколько, последовательные взятия перебирают их. Отпускание на Cancel внизу
удаляет связь и не открывает Add node.

## Типы нод

| Нода | Действие и настройки |
| --- | --- |
| Intercept | Ждёт завершённый HTTP-обмен или подходящее WS-сообщение. В HTTP-режиме ANY — любой метод; пустой Endpoint — любой. Request contains и Response contains — поиск подстроки, не регулярное выражение. Skip first пропускает N совпадений; Delay задерживает передачу результата после совпадения. |
| Rewrite | Delay откладывает включение перехвата, не блокируя сетевой поток. Проверяет Method, URL/Endpoint и Request contains. После Skip first меняет выбранное тело исходящего запроса или входящего ответа, не создавая второй запрос. Завершается после обмена. |
| Request | Отправляет Method, URL/Endpoint, Headers и Body. Delay — перед отправкой; Timeout — ожидание ответа; Retry count — число дополнительных попыток. Полный URL задаёт конкретный сервер; endpoint начинается с `/` и использует текущий клиентский сервер. |
| Socket | Отправляет UTF-8 текст или JSON через существующее WebSocket/MQTT-соединение. Настройки: URL/Endpoint, Topic, Body, Delay и Timeout. Topic обязателен для MQTT и пуст для обычного WS. URL, Topic и Body поддерживают переменные. Новое соединение не открывается. |
| Action | Вызывает действие меню: смена выбранного сохранённого аккаунта, Relog account, запуск/остановка выбранного маршрута или анимации. Запуск не ждёт завершения воспроизведения. Если воспроизведение уже остановлено, Stop ничего не меняет, но нода завершается успешно. |
| Condition | Сравнивает Value с Compare with: равно, не равно, больше, меньше, содержит или существует. Отправляет выполнение только в True либо False. Отсутствующий JSON-путь в проверке «Существует» даёт False; неправильный источник/JSON — ошибку. |
| Collect | Собирает активные источники под ключами `request`, `request#2` или `request.body` (для отдельного порта). As array создаёт массив в порядке связей. Неактивные ветки Condition не добавляются. |
| Read | Читает JSON из File после Delay. Если файл отсутствует, использует Default value. Если значение не задано — ошибка. Некорректный JSON и другие ошибки чтения не игнорируются. Результат доступен через Response и переменные следующих нод. |
| Save | Записывает JSON из Body в File после Delay. Расширение `.json` добавляется автоматически. Некорректный JSON не перезаписывает файл. |
| Notification | Показывает Notification text после Delay. Duration задаёт время показа; по умолчанию 5000 ms. Завершение ноды не ждёт исчезновения уведомления. |

### HTTP, WebSocket и MQTT

Request работает только с HTTP. У Intercept и Rewrite выбирается транспорт HTTP/WS.
В WS каждый кадр независим: Request contains проверяет исходящий кадр,
Response contains — входящий. Цель Rewrite задаёт направление; полная замена,
объединение полей и JSON-операции работают с UTF-8 телом.
Новое входящее WS-сообщение должно помещаться в родной буфер 2048 байт.
Правило одноразовое на итерацию.

Socket использует уже подключённое соединение; неактивное или закрытое
соединение завершится тайм-аутом. Для отправки не нужен новый входящий кадр.
Игровой WS URL копируется как эндпоинт, внешний адрес — полностью. Скопированная
текстовая публикация MQTT сохраняет Topic и отправляется как новая публикация
QoS 0, без повторного использования идентификаторов пакетов. Протокольная
оболочка MQTT остаётся двоичной, но Body ноды Socket должен быть UTF-8 текстом
или JSON. Входящие и непрозрачные двоичные данные нельзя копировать в Socket.

### Частичное изменение Body в Rewrite

Под URL/Endpoint выберите **Тело запроса** (по умолчанию) или **Тело ответа**.
В режиме ответа исходящий запрос не меняется: переписывается завершённое тело
ответа до передачи вызывающему коду клиента. Фильтры и Skip first проверяют
оригинальный запрос. Изменённый ответ должен помещаться в родной буфер;
если места недостаточно, нода завершается с ошибкой, исходный ответ сохраняется.

Rewrite нужно запустить **до** клиентского запроса. Intercept ждёт уже полученный
ответ, поэтому связь Intercept → Rewrite изменяет следующий совпавший запрос,
а не задним числом уже отправленный. Loop повторно ставит правило после завершения.

- Replace body — полная замена, включая не-JSON текст.
- Merge fields — вложенные поля добавляются/заменяются, `null` удаляет поле;
  остальные поля остаются. Массив заменяется целиком.
- Patch operations — массив операций `add`, `replace`, `remove`, `test` с JSON Pointer.
  `/users/1/name` адресует второй элемент, `/-` добавляет в конец массива;
  `~1` означает `/` в имени ключа, `~0` — `~`.

Merge fields, пример Body:

```json
{"name":"Новое имя","extra":true,"obsolete":null}
```

Patch operations, пример Body:

```json
[{"op":"replace","path":"/name","value":"Новое имя"},
 {"op":"add","path":"/extra","value":true},
 {"op":"remove","path":"/obsolete"}]
```

Если операция/путь некорректны или результат слишком велик, оригинальный запрос
остаётся нетронутым, а Rewrite завершается с ошибкой. Полный URL дополнительно
фильтрует сервер; endpoint сравнивается без query-параметров.

Для Request Client headers включает текущий набор заголовков клиента целиком.
Каждый заголовок можно отключить отдельно; поля только для просмотра.
Custom headers редактируются, отключаются и удаляются. Имена сравниваются
без учёта регистра: включённый custom header заменяет одноимённый клиентский.
Для внешних сервисов Client headers автоматически не отправляются.

HTTP 4xx/5xx с полученным ответом доступны дальше через Status/Response.
Сетевой сбой, тайм-аут или ошибка переменной останавливает сценарий после
исчерпания повторов. Stop прекращает планирование и ожидание; уже отправленный
запрос отменить на сервере нельзя.

## Секреты

Отключение Client secrets влияет только на видимость клиентских данных в интерфейсе;
передаваемые значения не изменяются. Значения пользовательских секретов визуально скрываются звёздочками `***`
и раскрываются при редактировании.

Добавьте имя и значение, например `telegram_bot` и ключ бота, затем используйте
`https://example.test/bot{{secret.telegram_bot}}/send` в URL. В поле имени уже
есть неизменяемый префикс `secret.` — вводите только `telegram_bot`.
Подстановка также работает в заголовках, фильтрах, телах запросов и Notification text.
Только настоящие скрытые значения показываются серыми `***`, включая URL
в Traffic stream. Подключение другой ноды не меняет именованные секреты.
Ссылки `{{secret.telegram_bot}}` и `{{client.session}}` остаются видимыми.
Inspector показывает исходные значения, включая клиентские и пользовательские секреты.

Пользовательские секреты сохраняются локально в общем кэше, отдельно от JSON
сценариев, открытым текстом: маскирование не является шифрованием. Не отправляйте
этот кэш другим людям. Ключ, введённый напрямую в сценарий, остаётся в его JSON;
используйте именованные ссылки.

## Переменные

`{{client.user}}`, `{{client.user_id}}` и `{{client.session}}` — текущие данные клиента.
Остальные переменные доступны из **прямо подключённых** предыдущих нод.
Отображаемое имя не участвует в синтаксисе: можно переименовать ноду с пробелами.

| Источники | Пример |
| --- | --- |
| Один | `{{users[1].age[1]}}` или `{{status}}` |
| Несколько Request | `{{request.users[1].age[1]}}`, `{{request#2.status}}` |
| Разные типы | `{{request.status}}`, `{{intercept.response.msg}}`, `{{rewrite.response}}` |

Номер `#2` соответствует второй ноде этого типа в графе, независимо от её имени.
Индексы массивов начинаются с нуля: `[1]` — второй элемент.
Префикс `response.` не обязателен для полей JSON-ответа:
`{{msg}}` равнозначно `{{response.msg}}`. Он полезен, если поле ответа называется
`method` или `status`: без префикса выбираются метаданные HTTP.

Метаданные: `method`, `url`, `endpoint` (путь с query), `headers`, `body`
(исходящее тело), `response` (полный ответ), `status` и `text` для Notification.
Поля JSON исходящего запроса: `{{body.lvl}}`, `{{request.body.users[0].name}}`;
значение заголовка: `{{headers.Content-Type}}`. Без префикса читаются поля ответа.
При копировании ноды из Network значения `user`, `user_id`, `session` в JSON
заменяются на `{{client.user}}`, `{{client.user_id}}`, `{{client.session}}`.
Объекты и массивы подставляются как JSON.

### Выражения

Типы JSON сохраняются. `exists` и `??` считают отсутствием только ненайденное
поле и null: `0`, `false` и `""` существуют. Обычная ссылка на отсутствующее поле
остаётся ошибкой; если отсутствие ожидается, используйте значение по умолчанию
или необязательный вывод.

| Назначение | Пример |
| --- | --- |
| Наличие / отсутствие | `{{exists(request.user.points)}}`, `{{!exists(request.user.points)}}` |
| По умолчанию | `{{request.user.points ?? 0}}` |
| Сравнения | `{{request.user.level >= 3}}` (`==`, `!=`, `>`, `<`, `>=`, `<=`) |
| Логика | `{{request.user.points > 0 && request.user.level > 0}}` (`&&`, `\|\|`, `!`) |
| Выбор значения | `{{request.user.active ? "Active" : "Inactive"}}` |
| Префикс | `{{"Name: "?request.user.name}}` |
| Суффикс | `{{request.user.name?" (user)"}}` |
| Оба | `{{"User: "?request.user.name?" (active)"}}` |
| Текст при отсутствии | `{{!request.user.name?"Unknown user"}}` |
| Необязательное поле | `{{optional("Name: ", request.user.name)}}` |
| Только существующие поля | `{{join(" \| ", optional("Name: ", request.user.name), optional("Level: ", request.user.level))}}` |
| Объединение текста | `{{"Name: " + request.user.name}}` |
| Подстрока | `{{contains(request.user.name, "Ali")}}` |
| Массив в текст | `{{join(", ", request.items)}}` |
| Размер | `{{length(request.items)}}` |
| Регистр | `{{upper(request.user.name)}}`, `{{lower(request.user.name)}}` |
| Пробелы / замена | `{{trim(request.user.name)}}`, `{{replace(request.user.name, "A", "B")}}` |
| Разделение | `{{split(request.message, ",")}}` |
| Форматирование | `{{format("Name: {}", request.user.name)}}` |
| Числа массива | `{{sum(request.numbers)}}`, `{{min(request.numbers)}}`, `{{max(request.numbers)}}` |
| Округление | `{{round(request.total, 2)}}` |
| Преобразование / тип | `{{number(request.user.points)}}`, `{{string(request.user.points)}}`, `{{type(request.user.points)}}` |

Приоритет от высокого к низкому: скобки/функции, `!`, `+`, сравнения порядка,
равенство, `&&`, `||`, `??`, затем `?:` и короткий `?`. При смешивании короткого
вывода с тернарным оператором используйте скобки. `&&`, `||`, `??`, `?:`
вычисляют только нужную ветку. Короткая запись `!field?"текст"` проверяет
отсутствие поля, а не значение false. Равенство учитывает тип (`1 != "1"`),
сравнения порядка требуют числа. `+` складывает два числа, иначе соединяет текст.

`join` пропускает отсутствующие/null/пустые части без лишних разделителей.
У `optional` можно третьим аргументом передать суффикс. `length` считает символы
UTF-8, элементы массива или поля объекта. `upper`/`lower` поддерживают ASCII,
Latin-1 и русский алфавит. `split` возвращает JSON-массив; пустой разделитель
разбивает строку на символы. В `format` используются `{}`, для буквальных скобок —
`{{`/`}}`. `round` принимает 0–12 знаков после запятой. Для пустого массива `sum`
возвращает 0, а `min`/`max` — null. Числовые функции массива требуют числовые элементы.
`number` принимает числовую JSON-строку или boolean; некорректное преобразование —
ошибка. `type` возвращает `missing`, `null`, `boolean`, `number`, `string`, `array`
или `object`. Выражения не выполняют код, не читают файлы и не отправляют запросы;
глубина, объём работы, создаваемые массивы и размер результата ограничены.

## Форматирование уведомлений

Круглая кнопка значка в заголовке переключает варианты badge. Кнопка палитры
перед Rename выбирает непрозрачный RGB-цвет. Нода, скопированная нода и само
уведомление используют один стиль. Значок и цвет сохраняются в JSON и работают
с Undo/Redo.

В Notification используется простое форматирование: `**текст**` — жирный текст,
`` `текст` `` — серый текст.

Для переноса строки используйте настоящий перенос или `\n`.
`\n` раскрывается только в собственном тексте Notification. Escape-последовательности
из `{{body}}`, `{{response}}` и других подстановок повторно не обрабатываются.

```text
**Статус:** {{status}}\nРезультат: {{response.msg}}
```

## Выполнение и файлы

Жёлтая обводка ноды и портов — работа/ожидание; зелёная — завершение,
красная — ошибка. Результат виден 3 секунды. Тонкий штрих движется по связи
только при передаче результата, не постоянно во время ожидания.
Interface animations отключает анимации, но не выполнение.

Смена аккаунта через Action ожидает подготовки и применения данных, но не
авторизации на сервере. Для ожидания входа подключите после неё Intercept
ответа авторизации. Запуск маршрута/анимации сразу продолжает сценарий,
не ожидая завершения воспроизведения; запуск анимации также выбирает её
в библиотеке Animations. Остановка сценария отменяет ожидающие ноды,
но не уже начатую смену аккаунта и не запущенное воспроизведение.
Для остановки воспроизведения используйте отдельные действия остановки.

Сценарии сохраняются в `SPT/Flows/Scenarios/*.json`, данные Save/Read —
в `SPT/Flows/Data/*.json`.
Save/Read допускают только имя файла, без путей и `..`; размер данных до 256 KiB.
Файловые операции выполняются в фоне и не блокируют меню.
Формат: `schema: "spt_node_v1"`, имя, repeat-флаг `loop`, массив `nodes`.
ID нод — числа от 1; позиция — `pos: {x, y}`. Исходящие связи находятся
в поле `connections` каждой ноды:
число — Flow-связь, объект `{node, output, input}` — связь конкретных портов.
`custom_headers` — один объект имя → значение; отключённые имена — отдельный список.
`client_headers` — boolean. Notification сохраняет `delay_ms` и `duration_ms`.

Перед выбором файла импорта показывается предупреждение:
тщательно проверяйте сторонние сценарии перед запуском.
